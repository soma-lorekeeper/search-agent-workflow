## 1. 확정 구성

```
variant   whole          청킹 없이 원고 전문을 1회 호출로 추출
schema    sav            quote / subject / attribute / value / claim_type / category / context
route     broadcast      claim_type 분기 없이 전 claim에 동일 채널 세트 + dedupe
graph     off            검색 결과의 [관련 그래프] 부록을 수집하지 않음
judge     p2, 단일 호출, reasoning_effort 미지정, n=1
```

재현 명령 (추출은 디스크 캐시가 있으면 LLM 호출 0회):

```bash
PYTHONPATH=. .venv/bin/python scripts/eval_claims.py --stage all      --variant whole --route broadcast
PYTHONPATH=. .venv/bin/python scripts/eval_claims.py --stage assemble --variant whole --route broadcast
PYTHONPATH=. .venv/bin/python scripts/eval_claims.py --stage judge    --variant whole --route broadcast
```

## 4. judge 컨텍스트 절감 경로

judge에 넘길 근거량이 최대 병목이었다. 세 단계로 줄였고 **도달률은 23/24로 불변**이었다.

| 단계 | 입력/편 | 무엇을 뺐나 |
|---|---|---|
| 라우팅 개선 직후 | 855,091 | — |
| 그래프 부록 미수집 | 283,540 | 앵커 1~2홉 이웃의 설명문·관계 트리플 재나열 |
| **노드 병합 문서고** | **24,854 (2.9%)** | 같은 노드의 중복 수납 |

핵심은 **중복이 곱셈으로 늘어나고 있었다**는 점이다. v1 기준 청크가 원본에 총 3,273회 실렸는데 고유 청크는 229개(평균 14.3배), v5는 27.2배였다. 문서고는 노드를 한 번만 싣고 claim은 별칭(`C014`/`F003`/`E02`)으로 가리킨다.

정보 손실이 없음은 구조화 필드로 검증했다 — 청크 `text` 전문 일치, 사실·개체·참가자·근거 연결·`story_order` 전부 보존.

| GT | 카테고리 | 점수 | 원인 |
|---|---|---|---|
| v3-GT3 | 소속/직업 | 1 | 근거를 받고도 놓침 |
| v3-GT4 | 신원/취미 | 5 | 근거를 받고도 놓침 (경계) |
| v4-GT1 | 생사 | 0 | 근거를 받고도 놓침 |

**7건 중 5건이 판정 실패다.** 근거는 문서고에 있었고 판정이 연결하지 못했다. 다음 개선의 주 대상은 검색이 아니라 판정이다.

근거로, `reasoning_effort=high`가 v3-GT3·v5-GT1을 잡았고(20/25), n=3 표본에서 v3-GT3 `[0,1,9]`·v5-GT2 `[0,1,9]`처럼 **표본 하나가 정답에 닿는** 패턴이 관찰된다.

## 7. 측정 시 반드시 지킬 것

**단일 실행으로 ±1건을 논하지 말 것.** 자기일관성 측정(`--judge-n 3`) 결과 claim의 25%가 표본마다 점수가 다르고, τ=7 경계를 넘나든 것이 6건(2%)이었다. 프롬프트 p1→p2의 "손실 1건"도 재측정하니 노이즈였다.

**흔들림은 GT에 몰린다.** 불안정한 6건 중 4건이 GT였다. 판정이 애매한 구간이 곧 진짜 오류가 있는 자리이므로, 개선 실험은 n=3 이상으로 확인해야 한다.

**hard-negative와 excluded를 갈라서 셀 것.** `hard_negatives`(v3의 4건, 시변 값 정상 변화)는 FP 벌점 대상이지만, `excluded`(원작 전개 변경)는 GT 파일이 "FP로 세면 precision이 부당하게 깎인다"고 명시한 채점 제외 항목이다.

**negative 표본은 3건뿐이다.** `[체력 Lv.1 → Lv.10]`은 추출 단계에서 걸러져 judge 판정 대상이 아니다. "0/3"은 오탐이 없다는 증거가 아니라 회귀 테스트 통과로 읽어야 하고, 통계적 무게는 라벨 없는 259개의 고득점 분포(0.4%)가 진다.

**소음률은 FP율이 아니라 상한이다.** 라벨 없는 259개는 정답이 없고, 6화 고유 사건은 근거가 없어 낮은 점수가 나오는 것이 정상이다.

## 8. judge 프롬프트 (p2)

`scripts/eval_claims.py`의 `_JUDGE_CRITERIA` + `_JUDGE_FEWSHOT`. 출력은 claim당 `{i, score(0~10), cited[], reason}`.

판정 원칙 7개 중 오탐 방지에 직접 기여한 것:

- **원칙 2 (시변 값)** — 수치·레벨·소지품은 진행에 따라 바뀐다. "변할 수 없다"고 못박은 근거가 있을 때만 모순. hard-negative 4건이 전부 이 유형이다
- **원칙 3 (예언·인용과 전개의 차이)** — `excluded` 유형을 겨냥
- **원칙 6 (`순서`로 선후 판단)** — p2에서 신설. 죽었다는 대상이 더 나중 순서의 사실에 참가자로 등장하면 "근거 없음"이 아니라 **적극적 반증**으로 읽으라는 지시. v1-GT3을 0점 → 9점으로 회수했다

few-shot 8개는 전부 지어낸 가상 소설이다 — 평가 대상 작품에서 따오면 기준 이해가 아니라 패턴 암기로 맞히게 된다. 점수를 9/8/9/1/1/0/0/8로 흩어 고득점 앵커링을 막았다.

`JUDGE_PROMPT_VERSION` 상수를 문안 수정 시마다 올려야 아티팩트가 덮이지 않는다.
