단계별 스펙

STAGE 0

배경 컨텍스트 준비

lorekeeper-poc의 context.py를 그대로 재사용 — dump_graph_text + load_summaries → build_context. 전역 줄거리 압축 + 최근 회차 요약 + 그래프 덤프를 하나의 텍스트로 합쳐 1·2단계에 공급.

STAGE 2

claim별 검증 에이전트 (fork · 병렬)

claim마다 독립 세션 — 시스템 프롬프트에 판정 규칙 + 0단계 컨텍스트 + 도구 4종을 실어 시작. 근거가 불충분(unknown)하면 계속, 충분하면 즉시 구조화 verdict로 종료.

왜 fork 안쪽만 에이전틱한가

설계 원칙

도구 선택에 불확실성이 있는 지점은 claim별 검증 하나뿐이다 — 어떤 claim이 entity_state_history로 바로 풀리고, 어떤 claim이 text2cypher_search의 집계 질의를 필요로 할지는 claim마다 다르고 미리 알 수 없다.

반면 컨텍스트 준비·claim 추출·결과 집계·리포트 생성은 "무엇을 할지"가 항상 정해져 있는 작업이라, 에이전틱 루프(도구 선택 판단)를 씌울 이유가 없다. 딱 필요한 지점에만 복잡도를 두는 것.

단일 에이전트가 claim 하나당 도구 선택 + 최종 판정까지 함께 맡는다 — 판정을 분리하지 않고, 예산(최대 4 tool call) 안에서 근거가 쌓이면 스스로 멈춘다.
